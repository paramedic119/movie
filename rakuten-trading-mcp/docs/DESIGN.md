# 楽天証券を MCP でつないで Claude が売買する方法（設計メモ）

2026年9月時点の公開情報をもとにした設計です。実装は同じフォルダの [`rakuten-trading-mcp`](../README.md) にあります。

> **大事なこと**
> - Claude は相場を予測できるわけではありません。この仕組みは「Claude の判断で発注できるようにする」ためのもので、利益を保証するものではありません。
> - 実際のお金が動くのは `mode = "live"` のときだけです。まずは模擬売買（paper）で十分に試してください。
> - 楽天証券側（マーケットスピード II RSS）との接続部分は公開ドキュメントをもとに実装しており、実際の口座ではまだ動作確認できていません（→ [7. 段階的な導入](#7-段階的な導入)）。

---

## 1. 結論

- 調べた範囲では、楽天証券は個人向けに**公式の発注 API（REST 等）も、公式の MCP サーバーも提供していません**。
- 楽天証券が公式に用意している自動発注の手段は **「マーケットスピード II RSS」（Excel アドイン）の発注関数**です（`RssStockOrder_v` など）。
- そこで、**Windows PC 上で「Excel + RSS」を Python から COM で操作する MCP サーバーを自作し、Claude（Claude Desktop / Claude Code）から呼ぶ**構成にします。

```
 ┌──────────────── 同じ Windows PC ─────────────────────────────────────────┐
 │                                                                            │
 │  Claude Desktop / Claude Code                                              │
 │        │  MCP（stdio）                                                     │
 │        ▼                                                                   │
 │  rakuten-trading-mcp（Python）                                             │
 │   ├ リスクチェック（銘柄・金額・回数・時間・価格乖離・キルスイッチ）      │
 │   ├ 人間の承認（MCP elicitation の確認ダイアログ）                        │
 │   ├ 監査ログ（誰が・何を・なぜ）                                          │
 │   └ ブローカー切替: paper（模擬）/ rss（本番）                            │
 │        │  COM（pywin32）                                                   │
 │        ▼                                                                   │
 │  Excel + マーケットスピード II RSS  ──  マーケットスピード II（ログイン中）│
 └────────────────────────────────────────│───────────────────────────────────┘
                                          ▼
                                     楽天証券
```

Claude はツールを呼ぶだけで、**発注の可否を最終的に決めるのはサーバー側のチェックと人間の承認**です。Claude に何を言われても（プロンプトインジェクションを受けても）、サーバーの制限は越えられないように作ります。

## 2. 接続手段の比較

| 方式 | 対象 | 発注 | 公式の手段か | 評価 |
|---|---|---|---|---|
| **A. マーケットスピード II RSS（Excel）+ COM** | 国内株（現物・信用）、先物OP 等 | ○ | ○（RSS の発注関数） | **採用**。Windows と Excel が必要で、Excel と マーケットスピード II を起動しておく必要がある |
| B. Web サイトをブラウザ自動操作・スクレイピング | 何でも | ○ | ✕ | **非推奨**。規約上のリスク、ログイン保護や画面変更で壊れる、誤クリックが誤発注に直結する |
| C. 楽天FX + MT4（EA） | FX のみ | ○ | ○（MT4） | FX に限れば選択肢。MCP から使うには MT4 との橋渡しが別途必要 |
| D. 他社の公式 API（例: 三菱UFJ eスマート証券〔旧 auカブコム証券〕の kabuステーション API） | 国内株 等 | ○ | ○（REST） | 楽天証券にこだわらないなら最も素直。これも専用アプリを起動した PC 上で動かす |
| 参考: マネックス証券「MONEX MCP Server」（2026年8月〜） | 口座情報の照会 | ✕ | ○ | 証券会社公式の MCP だが、照会のみで発注はできない |

楽天証券で発注まで行うなら、現実的に A しかありません。本実装は、ブローカー部分を差し替えられる作りにしてあるので、D に切り替える場合も MCP のツールやリスク管理はそのまま使えます。

## 3. MCP ツール設計

| ツール | 内容 | 状態を変えるか |
|---|---|---|
| `get_status` | モード（paper/live）、承認方式、取引時間か、リスク上限、本日の残り枠 | – |
| `get_quote` | 現在値・前日終値・四本値・出来高・最良気配（`RssMarket`） | – |
| `get_price_history` | 分足〜月足のローソク足（`RssChart`） | – |
| `get_account` | 買付余力・保有銘柄・評価損益（`RssPositionList` / `RssCapacityList`） | – |
| `list_orders` | 本日の注文・未約定注文（`RssOrderList`） | – |
| `preview_order` | リスクチェックだけ行い、通れば**確認トークン**を返す（発注しない）。`reason`（売買の根拠）必須 | – |
| `place_order` | 確認トークンの注文を発注（`RssStockOrder_v`）。承認方式 `elicit` ではユーザーに確認ダイアログ | **発注** |
| `cancel_order` | 未約定注文の取消（`RssCancelOrder_v`） | **取消** |
| `get_journal` | 監査ログ（判断理由つき）で過去の判断を振り返る | – |
| `get_report` | 模擬売買の成績（評価額の推移・騰落率・最大ドローダウン・約定数・各銘柄を持ち続けた場合との比較）。paper のみ | – |
| `advance_day` | リプレイ（過去の日足での早送り）を次の取引日に進める。リプレイ中のみ | 模擬の時計 |

発注を `preview_order` → `place_order` の 2 段階に分けているのは、

1. Claude が発注前に必ずリスクチェックの結果（概算金額・警告）を見る
2. 確認トークンは 1 回限り・180 秒で失効するので、再試行などで同じ注文が二重に出ない
3. 人間の承認ダイアログに出す内容を、プレビュー時点の内容に固定できる

ためです。

## 4. 安全設計

### 4.1 人間の承認（2 方式）

| `approval_mode` | 承認のしかた | 向いている使い方 |
|---|---|---|
| `elicit`（既定・推奨） | `place_order` の実行前に、**サーバーが**確認ダイアログ（MCP の elicitation）を出す。「この注文を発注する」をオンにして承認した注文だけが発注される | 対話しながら売買する |
| `client`（おまかせ） | サーバー側では確認しない。Claude Code の「ツール実行の許可」に任せる（`init --delegate` で発注・取消を事前許可） | 予算を決めて任せる・無人のスケジュール実行 |

`elicit` のポイントは、承認の結果がモデルの入力（ツール引数）ではなく**クライアントから直接サーバーに届く**ことです。Claude が「承認済み」と書いて呼び出すことはできません（実装では MCP Python SDK の `Resolve` / `Elicit` を使い、起動時に `place_order` の入力スキーマが `confirmation_token` だけであることを検査しています）。確認ダイアログに対応していないクライアントでは発注できずに止まります（安全側に倒れる）。

MCP の新しいプロトコル（2026-07-28 版）では確認ダイアログの受け渡し方が変わりましたが、SDK が旧方式・新方式の両方に対応しており、テストでも両方を確認しています。

`client`（おまかせ）では人間の確認がなくなるので、代わりに次の「予算」で Claude が動かせる金額を区切ります。実弾（live）でおまかせにする場合、予算の設定は必須です（設定がないと起動しません）。

### 4.2 リスク制限（サーバー側で必ず実行）

`preview_order` の時点と、承認後の発注直前の 2 回チェックします（承認を待つ間に価格が動くことがあるため）。

| 制限 | 既定値（例） | 目的 |
|---|---|---|
| 売買してよい銘柄のリスト | 設定で指定 | 想定外の銘柄を触らせない |
| 1 注文の上限金額 / 1 日の買付合計 / 1 銘柄の保有上限 | 10万円 / 30万円 / 30万円（`init` は予算に合わせて設定。100 株単位で値がさ株も買えるように） | 損失の上限を決める |
| 指値と現在値の乖離 | ±3% | 桁違いなどの誤発注を防ぐ |
| 成行注文 | 禁止 | 板が薄いときの想定外の約定を防ぐ |
| 1 日の発注回数・取消回数 | 10 回 / 10 回 | 暴走や、見せ玉と誤解される発注・取消の繰り返しを防ぐ |
| 発注の最小間隔 | 30 秒 | 同上 |
| 日次の損失上限 | 3万円（超えたら新規の買いを停止。売りは可） | 負けが込んだときに止める。予算が有効なら予算の評価額で判定（live でも有効）。予算なしの live では RSS から評価額合計を確実に取れないため判定しない |
| 取引時間 | 東証の立会時間のみ（祝日は設定） | 時間外の注文が翌営業日に執行されるのを防ぐ |
| 保有数を超える売り | 禁止（空売りはしない） | 信用取引の意図しない建玉を防ぐ |
| キルスイッチ | `data/STOP` ファイルがあれば全停止 | すぐに止める手段 |

日次の回数・金額は監査ログから毎回集計するので、サーバーを再起動しても残り枠は戻りません。並列のツール呼び出しでチェックをすり抜けないよう、チェック〜発注〜記録は直列化しています。

### 4.3 予算（Claude に任せる金額）

`[budget]` を有効にすると、許可銘柄（`risk.allowed_symbols`）の売買を「Claude の持ち分」として台帳（`data/budget.json`）で管理し、次のルールをサーバー側で強制します。予算の金額は設定ファイルでしか変えられないので、Claude が自分で枠を増やすことはできません。

| ルール | 内容 |
|---|---|
| 買える金額 | 予算 − Claude が持っている株の取得原価 − 未約定の買い注文の拘束額（損失はここから差し引く。利益の上乗せは `reinvest_profits = true` のときだけ） |
| 損失上限 | 確定損益 + 含み損益 が −`max_loss_jpy` に達したら新規の買いを止める（売りは可） |
| 売れる株 | Claude が予算で買った株だけ。予算を始める前から持っていた株は「あなたの持ち分」として扱い、売らない |

台帳の付け方:

- 口座の保有数量が前回見たときから増減していたら、その銘柄の Claude の注文（監査ログ）が約定したとみなします。Claude の注文と対応しない増減は、あなた自身の売買として「あなたの持ち分」の側を動かします。同じ注文を二重に数えないよう、注文ごとに約定として数えた数量を記録します。
- 約定価格は、証券会社の約定単価が取れればそれを、取れなければ Claude の注文の指値を使います（買いは高め・売りは安めに見積もるので、予算の残りは実際より少なめ＝安全側になります）。
- 発注から監査ログへの記録までの間に照合が走ると、すぐに約定した分を取り違えるおそれがあるため、発注〜記録と照合は直列化しています。

前提として、**予算で運用している銘柄を、手で同時に売買しないでください**（Claude の注文と同じ日に同じ銘柄を手で売買すると、区別が付かなくなることがあります）。

### 4.4 監査ログ

`data/audit/YYYY-MM-DD.jsonl` に、プレビュー・拒否・承認拒否・発注・取消・予算の約定を**判断理由（`reason`）つき**で記録します。Claude 自身も `get_journal` で過去の判断を振り返れます。

### 4.5 実弾モードの二重確認

`mode = "live"` にしても、環境変数 `RAKUTEN_MCP_LIVE=yes` がないと起動しません（`init --live` は `.mcp.json` にこの環境変数を書き込みます）。設定ファイルの書き間違い（未知のキー）もエラーにします（例: `max_order_value` と書いて上限が効いていない、という事故を防ぐ）。

## 5. RSS 連携の詳細

- Python から `pywin32` で起動中の Excel に接続し、専用ブック（既定 `mcp_bridge.xlsx`）の作業シートに RSS 関数を書き込んで値を読みます。COM はスレッドに縛られるので、専用スレッド 1 本で直列に実行します。
- 株価: `=RssMarket("7203.T","現在値")` のような式を銘柄ごとに 1 行ずつ置き、リアルタイムに更新される値を読みます（関数の数が増えすぎないよう、行は使い回し）。
- 一覧（保有・余力・注文・発注ID）: `RssPositionList` / `RssCapacityList` / `RssOrderList` / `RssOrderIDList` をシートに置き、見出し行を探して表として読みます。列名が想定と違っても設定で直せるようにしています。
- 発注: `Application.Run("RssStockOrder_v", 発注ID, 銘柄コード, 売買区分, 注文区分, SOR区分, 数量, 価格区分, 価格, 執行条件, 注文期限, 口座区分)`。
  - 売買区分 1=売 / 3=買、価格区分 0=成行 / 1=指値、執行条件 1=本日中（本実装は「本日中」の通常注文のみ）。
  - 発注IDは Excel を再起動するまで再利用できないため、ファイルに保存して単調増加させます。
  - 発注後、`RssOrderIDList` で注文番号と発注結果を確認します。
  - 二重発注を避けるため、発注と取消の呼び出しは自動リトライしません。
- 取消: `Application.Run("RssCancelOrder_v", 新しい発注ID, 注文番号)`。

## 6. Claude が売買する使い方

Claude が動くのは、**あなたの PC 上で動いている Claude のセッション**の中です（楽天証券への発注は PC 上の Excel 経由でしかできないため、クラウドで動く Claude からは直接売買できません）。`python -m rakuten_trading_mcp init` が、そのフォルダで起動した Claude Code がすぐ使えるように設定一式（`.mcp.json`・`.claude/settings.local.json`・`config.toml`）を作ります。

### 6.1 対話型・確認あり（おすすめの始め方）

Claude Code（または確認ダイアログに対応したクライアント）で、例えば次のように頼みます。

> get_status を確認してから、保有銘柄と 7203 の日足 60 本を見て、今日買うべきか判断して。買うなら理由を書いてプレビューまで出して。

Claude が `preview_order` → `place_order` まで進むと、確認ダイアログが出ます。内容と理由を見て承認したときだけ発注されます。

### 6.2 対話型・おまかせ（予算つき）

`init --delegate --budget 300000 --symbols ...` で作り直すと、確認ダイアログなしで Claude が発注・取消します。

- 「予算の範囲で売買して」と頼めば、Claude は `get_status` の予算の残りを見ながら判断します。予算・損失上限・売れる株の制限はサーバーが強制します（4.3）。
- Claude Code の `/loop 30m …` で、開いている間は定期的に判断させられます。
- PC で `claude remote-control` を実行しておけば、その会話にスマホの Claude アプリからも参加できます。

### 6.3 無人のスケジュール実行

Windows のタスクスケジューラで、平日の決まった時刻（例: 9:30 / 13:00 / 14:30）に Claude Code をヘッドレスで起動します（`examples/scheduled_session.ps1`）。

- ヘッドレス実行では確認ダイアログを出せない（キャンセル扱いになる）ため、おまかせ設定（`init --delegate --budget ...`）が前提です。`--allowedTools` でも使ってよいツールを明示します。
- 無人運用では、リスク上限を対話型よりさらに小さくし、Web 検索などの外部情報のツールは許可しないことをおすすめします（Web ページに仕込まれた指示で判断が歪められるリスクがあるため）。
- 売買ルールはプロンプト（`examples/session_prompt.md`）に明文化し、「迷ったら何もしない」を明記します。

### 6.4 Claude に任せないほうがよいこと

Claude は呼ばれたときにしか動きません。**損切りを Claude の巡回に頼るのは危険**です。損切りは証券会社側の逆指値注文で置いておくのが確実です（本実装では未対応。今後の拡張候補）。

### 6.5 Linux で使う

楽天証券への発注手段（マーケットスピード II RSS）は Windows の Excel アドインなので、**Linux だけで楽天証券に発注することはできません**（Wine などで Excel と RSS を動かすのも現実的ではありません）。Linux では目的に応じて次のように使い分けます。

| やりたいこと | 方法 | 必要なもの |
|---|---|---|
| 過去の相場で Claude の売買を試す（リプレイ） | `init --replay 開始日:終了日` → `fetch` → Claude が `advance_day` で 1 日ずつ進めながら売買し、`get_report` で成績を見る | J-Quants API の無料プラン（12 週間遅れ・過去約 2 年分）で足りる |
| 本物の株価で毎日の模擬売買 | `init --market-data csv` → 毎営業日の夕方に `fetch` と Claude を実行（`examples/linux/daily_session.sh` を cron や systemd タイマーで） | 当日の日足が要るので J-Quants の有料プラン（ライト: 月額 1,650 円、引け後に当日分） |
| 楽天証券で実際に発注 | Windows の PC（または Linux 上の Windows 仮想マシン）で、Excel + RSS と Claude Code を動かす | Windows・Excel・マーケットスピード II RSS |
| Linux から実際に発注 | OS を問わない API がある証券会社のブローカーを追加する（例: 立花証券 e支店 の API。口座があれば無料で、HTTP なので Linux から使え、デモ環境もある） | 未実装。`brokers/` に追加すれば、リスク管理・予算・監査ログはそのまま使える |

日足での模擬売買（`paper.market_data = "csv"`、`DailyBarPaperBroker`）の約定モデル:

- 大引け（15:30）後・休日に出した注文は翌営業日の足、大引け前に出した注文はその日の足で判定します。その足が確定して取得されるまでは未約定です。
- 寄り付き前（前日の大引け後を含む）に出した指値は、始値が有利なら始値で、日中に指値に届けば指値で約定します。取引時間中に出した注文は、すでに過ぎた始値では約定させず指値で約定させます（控えめな見積もり）。届かなければ失効（本日中の注文）。
- 当日の足は大引け後まで見せず、リプレイでは「今日」より後の足を一切見せません（先読みの防止）。
- J-Quants の調整済み四本値（株式分割・併合を調整した値）を使うので、期間中に分割があっても株価が不連続になりません。
- 日々の模擬売買では、最新の足が 10 日より古いと株価を返さず、古い株価での発注を防ぎます。

リプレイでは時計が「その日の大引け後」で止まっているので、取引時間と発注間隔のチェックは行いません（それ以外のリスク制限と予算はそのまま効きます）。リプレイの記録は通常の模擬売買と混ざらないよう別のフォルダ（`data-replay`）に置き、期間の違う記録が残っていると起動しません。

## 7. 段階的な導入

1. **paper + static**（どの OS でも）: サンプル株価で、ツールの動き・確認ダイアログ・リスク拒否を確認する。
2. **paper + 日足のリプレイ**（どの OS でも）: 過去の期間を早送りして、Claude の売買ルールの成績を `get_report` で確かめる（6.5）。
3. **paper + RSS の株価**（Windows）: `paper.market_data = "rss"` にして、本物の株価で模擬売買する。`check` コマンドで株価と一覧シートの読み取りを確認し、列名の違いは設定で直す。
4. **live・極小**: 上限をごく小さくし（例: 低位株 100 株だけ）、約定しにくい指値で発注 → 取消 を試して、発注ID・注文番号・取消が正しく動くことを確かめる。
5. **live・小額運用**: 対話型（確認あり）で少額から。監査ログで Claude の判断を振り返りながら、ルールと上限を調整する。
6. **おまかせ**: 予算を小さく決めて `init --live --delegate --budget ...`。必要なら `/loop` や無人運用へ。

## 8. 法令・規約・リスク

- **自分の口座を自分のために**運用する範囲の話です。他人の資金を運用したり、売買の判断を有償で提供したりすると、金融商品取引法上の登録（投資運用業・投資助言業など）が必要になる場合があります。
- 自動売買でも**不公正取引**（約定させる気のない注文を出して取り消す見せ玉、仮装売買、相場操縦など）は禁止です。発注間隔・取消回数の制限はその予防も兼ねています。
- RSS の発注機能は、楽天証券の「マーケットスピード II RSS の利用に関する確認書兼同意書」に同意したうえで、**利用者の責任で**使うものです。誤発注の損失は利用者が負います。
- NISA 口座で自動売買すると非課税枠を意図せず消費します。既定の口座区分は特定口座（`rss.account_type = 0`）にしていますが、コード値は公式ヘルプで必ず確認してください。
